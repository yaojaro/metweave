# 格点填色施工笔记（v0.3，2026-10-06）

> 本文件是「格点填色」线的施工底档与决策记录：架构（垂直切片×微内核）、温度切片
> （第一切片）的设计选型与验收口径、逐要素生长的规矩。数据形态与要素矩阵的调研结论
> 已沉淀进各要素档案与 docs/grid-notes 本身的选型表（以 `@metweave/grid` 实现面为准）。

## 一、架构：垂直切片 × 微内核

14 个气象要素各一条垂直线（取数→转换→渲染→演示），做完一个即可独立运行展示；共享代码
收敛为「微内核＋要素档案」两层，按要素需求逐步生长——**加要素＝加档案文件＋进主示例页
图层面板清单，内核与适配层零改动**（后续「零新能力」要素是这一主张的试金石）。

```
@metweave/grid
  core.ts          双线性插值·分级函数·renderToImageData（纯函数、零 DOM）
  element.ts       ElementProfile 共享类型＋buildColorScale（档案→色标装配）
  elements/*.ts    每要素一文件（换算/色标/档位/渲染形态——单一事实来源，档案间零 import）
  convert.ts       GRIB2→viz-ready（./convert 子路径，Node 侧，建成即冻结复用）
@metweave/leaflet
  addGridLayer     宿主适配（渲染→canvas PNG→L.imageOverlay 独立 pane 贴像元边界）
examples/index.html 主示例页「格点图层」面板（格点背景场与实况站点同屏；数据三层语义＋拉最新）
```

**viz-ready 防火墙**：演示与内核开发只吃 `.mwgrid` 文件（容器头 JSON＋big-endian
float32），不依赖解码器进度——任何要素的渲染线可拿 eccodes 离线预产数据先行开发；
GRIB2 解码只服务「用户本地拿最新」链路（dev 中间件→gen:grid CLI，全在 Node 侧，
「GRIB 不进浏览器」红线）。

**只加不改**：新模式/新选项以加法进入内核（log 变换、哨兵透明、等值线、阈值档——
各自随对应要素引入）；既有要素的渲染像素由快照测试锁死，任何回归 CI 即红。

## 二、温度切片（第一切片）设计选型

| 决策点                   | 选型                                                                                                          | 理由                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 分位数实现               | 直读容器头预计算八分位梯子（p10/p25/p50/p75/p90/p99＋min/max），档案声明分位点、梯子外取值显式抛错            | 免全量排序（头里现成）；档位精度＝梯子级距，对色斑图扫视够用；不静默近似——口径漂移比报错难查 |
| renderToImageData 分辨率 | 逐像素对**场值**双线性取样（不是放大已着色像素），输出宽解耦于网格列数；`addGridLayer` 缺省 2× 列数超采样     | 超采样出平滑档界（无网眼）；降采样出抗锯齿聚合；GFS 中国域 280×160×2 亚毫秒级                |
| 缺测语义                 | 权重非零的参与格点任一 NaN → NaN → 像素 alpha 0；权重为零的邻点不参与判定                                     | 不跨缺测插值（缺测邻域的推测值比透明糟）；精确落在格点上读值恒为该点原值                     |

## 九、CAPE 切片落地（第四要素，2026-10-07）——阈值档＋档级透明两能力

`capeProfile`（`elements/cape.ts`）＋内核两能力＋面板清单一行＋图例阈值档适配——
预告位「哨兵透明＋阈值档（CAPE/反射率/能见度）」的前半落地。实测头口径
（`cape_cn.mwgrid` 容器头核对）：CAPE/sfc/**J kg-1**（容器头原串，显示取惯用 J/kg）、
无换算、toDisplay 恒等；中国域窗 0–3026 J/kg、p50=1、p10=p25=0——零值堆约 45%
（全球场调研 0–4951、p50=2 同构），分位数档塌在零上的失效实证即本片设计的出发点。

### 阈值档（threshold mode）

- `thresholdBreaks(thresholds)`：校验严格递增（复用 assertBreaks 口径——非有限/非
  递增抛错；空表合法＝恒单档，与 quantileBreaks 空分位点同口径）后**原样返回**
  （拷贝新数组不别名入参）。看似平凡，意义在把「显式业务阈值」确立为与等距/分位并列
  的**一等分级模式**——档位语义来自气象惯例而非场分布（CAPE 1000/2500/4000 的
  无/中度/强/极强对流潜势、表 B 定案），跨时次可比且不受零值堆牵连。
- `ElementProfile.defaultMode` 扩为 `"equal" | "quantile" | "threshold"`；`thresholds?`
  （显示单位空间——与 equal 域同规约，不经 toDisplay）加入类型面；`buildColorScale`
  加 threshold 分支（thresholdBreaks 直装配，stats 全程不读——分位数分支的镜像对立面）。
- **类型面取舍**：`equal`/`quantile` 由必填改**可选**（threshold 要素不背不用的等距域，
  cape 即不立两推荐——分位失效实证、等距无惯例锚，单一推荐模式）；不选判别联合
  （defaultMode 判别）是因为它会使 `{ ...tmpProfile, defaultMode: "quantile" }` 类
  spread 派生（既有测试与 README 示例的用法）编译红——加法生长不破既有编译面。
  模式与推荐参数的配对校验移入 `breaksOfMode` 统一把守（缺参显式抛错，运行时兜笔误）。

### 档级透明（transparent bins）——落位选型与理由

- **落位①：`ColorScale.transparentBins?: ReadonlySet<number>`（档序号集）**，不落
  RenderOptions/profile 专属配置。理由：
  1. **档序号的语义锚**：透明档以档序号表达，序号只有相对某份 breaks 才有意义——
     色标恰是「断点＋着色」的复合单元，档级透明是着色决策，随色标走最内聚；
     RenderOptions 是逐渲染调用参数（width/opacity/convert），管不着档结构；
  2. **与 addGridLayer 的 scale 覆盖天然兼容**：自定义 scale 自带 transparentBins
     即可携带透明意图，不带的即全档着色（显式覆盖、不静默继承档案缺省——README 立据）；
  3. **通用性（后续切片复用的形态）**：反射率 −20 无回波哨兵在阈值档设计下天然独占
     首档（首断点 > −20），「哨兵透明」退化为档级透明的特例 `transparentBins: [0]`——
     同一机制覆盖 cape（零值堆首档）与 refc（哨兵首档）；真值与哨兵同档的场景（值级
     透明）本片不实现，若将来出现再以加法引入独立字段，不占本字段。
- profile 侧配套 `transparentBins?: readonly number[]`（档案声明用数组——字面量立档
  友好；`buildColorScale` 装配进色标时转 Set——渲染逐像素 O(1) 成员判定，档序号与
  显示单位无关）。语义约束：**命中档 alpha 0、RGB 0（与缺测透明同一像素形态）**，
  与整体 opacity 无关（透明档不因滑杆复活）；缺省缺席＝无透明档＝行为不变。
- **零漂移论证**：渲染循环内的新判定 `bin < 0 || transparentBins?.has(bin)`——
  无该字段的既有色标走 `undefined` 短路，无任何算术路径变化；透明档仍占色带取样位
  （档数=breaks+1 不变，colorAt 的 (bin+0.5)/bins 与透明无关——测试断言有无透明档的
  着色档像素逐字节一致），tmp 冻结基线像素 sha 快照零漂移收口。
- 序号校验：整数且 0 ≤ 序号 ≤ breaks.length（渲染前与断点/色带校验同一道关口）——
  越界序号是配置笔误，静默不生效比报错难查（不静默纪律）。

### CAPE 档案与图例

- 色标暖色渐进（ColorBrewer YlOrRd 9 停靠，浅→深＝弱→强——对流惯用黄→橙→红系）；
  4 档取样 t=0.375/0.625/0.875，可见三档落黄橙/红橙/深红，透明首档占 t=0.125 位不画。
- 等值线 500 J/kg 留位（无特值线）；renderForm "filled"。
- 图例阈值档适配（`legendTickValues`）：刻度＝**场最小值＋阈值本身**（cape 实测即
  0/1000/2500/4000）——值少全标（通用抽样 step=1 兜底，阈值多时至多 ~9 档）；**无上缘**
  （末档 [4000,∞) 外延无界，标上缘即谎称有界域）；**透明首档不标**（透明无值可读，
  刻度序列自首阈值起即可读出「以下透明」）。「拉最新」/三态/缓存零改动复用
  （gen CLI 与中间件本就按要素键泛化）。
- 测试：thresholdBreaks 校验面（含拷贝语义）、透明档像素断言（命中档 alpha 0/RGB 0、
  相邻档逐字节不受牵连、opacity 不复活、缺省全档着色、序号校验含末档合法位）、
  cape 档案口径锁（照 rh.test 结构 7 例，含渲染集成断言）、buildColorScale threshold
  分支（stats 全缺测也不读）＋模式缺参抛错；既有 tmp/dpt/rh 档案测试仅因 equal/quantile
  转可选加了非空断言（断言集不变）。

## 十、降水率切片落地（第五要素，2026-10-07）——log₁₀ 前置变换

显示 mm/h（×3600，档案层换算红线维持）；中国域窗实测（2026-10-06T18Z f000）
0–14.1 mm/h、p50=0、**零值堆 74.3%**（全球调研 43%，无雨窗更极端）、0–0.1 mm/h
微量另占 13.5%、≥0.1 mm/h 仅 12.2%、无负值——对数偏态＋零值堆的典型形态。

### log₁₀ 前置变换（logScale）——变换落位选型与理由

- **落位：`ColorScale.logScale?: true`（渲染入口 `renderToImageData` 在定档前对值与
  断点统一取 log₁₀；断点循环外一次预变换、值逐像素变换）**，断点（breaks）声明留在
  **显示（线性）空间**（0.1/1/5/10 人类可读，与 equal 域同规约）。理由：
  1. **值侧与断点侧变换必须原子地同处一处**：对数定档要求值与断点在同一空间——若把
     变换交给调用方分别复合 RenderOptions.convert（值侧）与断点预处理（断点侧），
     忘一侧即静默错档且难查（档位口径漂移比报错难查）；收进渲染入口一处复合，配置
     错误面最小。备选「装配层把断点换进对数空间再进色标」被否：breaks 的显示单位
     契约（图例直读、自定义 scale 覆盖位同规约）会被破坏，等于把对数口径泄漏给
     所有读断点的下游；
  2. **breaks 线性契约不破**：图例（legendTickValues 直读）、README 断点示例、
     `addGridLayer` 的 scale 覆盖位全部零适配——log₁₀ 只是「定档空间」的口径，不是
     断点表达口径；
  3. **与档位模式正交**：threshold＋log₁₀＝本片组合（thresholdBreaks 原样可用，
     等距/分位模式同理可组合）——机制进档案声明（`ElementProfile.logScale?: true`，
     `buildColorScale` 装配透传），后续对数偏态要素复用；
  4. **零漂移**：无 logScale 的色标走 `undefined` 短路、breaks 原引用直用，既有算术
     路径不变——tmp 冻结基线像素 sha 快照零漂移收口（测试另锁 logScale 显式
     undefined 与缺席逐字节一致）。
- 校验：log 模式断点须为正（log₁₀(≤0) 无意义——线性空间合法的 0 断点在此即红），
  渲染前与断点/色带/透明档校验同一道关口；log₁₀ 单调递增，线性空间严格递增的断点
  变换后仍严格递增，无需二次校验（左闭右开边界语义在对数空间天然保持）。

### 零值通道——档级透明显式声明，−Inf 通道天然兜底

- **档案显式 `transparentBins: [0]`**（与 cape 同构）：表 B 定案「零值**首档**透明」
  ＝首档整体 [0, 0.1) mm/h 透明——恰零值之外，0–0.1 mm/h 的微量毛毛雨同样无信号
  价值（本窗实测 13.5%），不透明则近九成像素被近零浅色糊底、底图不可读；
- **log₁₀(0)=−Inf 走 `binIndexAt` 非有限通道返回 −1（透明）**——内核既有语义零新
  代码，恰零值经此通道、非零微量经档级透明，**两路像素形态相同（alpha 0、RGB 0），
  不区分语义**（同为「无信号透明」，图例刻度序列自首阈值 0.1 起，透明首档不标）；
- 负值（数值噪音）log₁₀→NaN 走同一非有限通道透明，与缺测同形态兜底。

## 十三、海平面气压切片落地（第八要素，2026-10-07）——等值线主导形态

`prmslProfile`（`elements/prmsl.ts`）＋内核两能力（`contours.ts`：contoursOf/centersOf，
d3-contour 为 @metweave/grid 唯一运行时外部依赖——owner 2026-10-04 终批）＋适配层一件

PRMSL/msl/**Pa**、显示 hPa（÷100）；中国域窗实测（2026-10-06T18Z f000）
1000.6–1039.7 hPa、p50 1015.3（表 A 全球调研 941–1047 同构）——连续场、低压中心＝内容锚。

### 等值线渲染落位选型（本片主设计题）

三个候选：① renderToImageData 扩展为可叠画线条层（线栅格化进同一 ImageData）；② 内核出
线条几何、leaflet 层出 SVG 叠层；③ `L.svgOverlay` 整块 SVG 拉伸。**定案＝②**：

- 标注文字是硬约束（任务书：「缩放下不失真——SVG 优于栅格」）：①的文字要进栅格即需
  内核自带字体光栅化（零 DOM 纯函数内核自造字体远超切片边界），缩放即糊；
- ①还要求动 renderToImageData 的渲染循环——既有七要素像素零漂移是纪律红线，加分支
  即加回归面（本片最终 renderToImageData 零改动，tmp 冻结基线快照原样绿）；
- ③整块 SVG 随缩放拉伸，文字同步放大缩小（矢量不失真但不是「恒定像素可读」——地图
  文字惯例是 zoom 下字号不变），要恒定字号还得在 zoom 事件里反向缩放文字，不如直接
  用 polyline＋divIcon 标记走 Leaflet 原生矢量管线（缩放重投影、命中、z 序全托管）；
- 落位：`addContourLayer` 独立 API（不并入 addGridLayer 返回复合层）——色斑层与等值线
  层在宿主手里可独立取舍（自定义色卡盖 fill 不必连等值线一起换），pane 分层
  （mw-grid z 350 / mw-grid-contour z 360 / 宿主矢量 ≥400）天然给出「色斑之上、站点之下」。

### contoursOf 的口径细节

- **threshold 序列**：显示空间值场上取 (min, max) 开区间内的 interval 整数倍∪
  minorInterval 整数倍∪场内特值，去重升序喂 d3-contour；兼为 interval 倍数的值归
  major 线种不重复出线（4/2 双密度＝2 hPa 细线、4 hPa 粗线各画一遍）。端点上的倍数
  不出线（贴边环无信息量）；场外特值静默跳过；min/max 从场值现算（不读容器头
  stats——等值线几何直接依赖场真值）。
- **坐标换算退半格**：d3-contour 点空间 ⟨i+0.5, j+0.5⟩＝格点中心（测试首跑即抓到的
  偏移 bug——不退半格则等值线整体偏半格、与色斑档界错位）；退半格后与
  renderToImageData 像素中心采样、gridOverlayBounds 半格外延同一几何口径。
- **缺测语义**：d3-contour 把 NaN 按「低于一切阈值」处理，等值线环绕缺测孔不穿越
  （实测 5×5 场 NaN 孔的环沿孔方界绕行）——与色斑渲染缺测透明、双线性不跨缺测插值
  同一纪律；viz-ready v1 容器规格当初就按此对齐（format.ts 文件头）。
- 性能：中国域 280×208、2/4 hPa 双密度 19 条线 684 环 17ms（Node）——加密线成本可忽略，
  照实现（任务书「按渲染成本裁量」的裁量结论）。

### 数值标注与 L/H 中心标注

- **数值标注只挂常规线与特值线**（加密细线气象惯例不标值）：每环按近似长度（经度分量
  按纬度余弦折算）决定标注数（≥3° 才标、每 10° 一处至多 3 处），沿弧长均匀取点，
  divIcon＋白底挖空描边（text-shadow 四向白晕）、恒定像素字号；全局标注预算 140、
  超预算长环优先（小环碎片信息量低）。
- **中心检测两轮选型**（真实场实证，本片最大的口径迭代）：纯八邻域极值在中国域
  热带海区出千级涟漪候选（0.1–0.5 hPa 格点噪音）；改「d 深度盆地闭合」判据
  （泛洪出界即弃）后误杀两类真系统——槽嵌系统（台风联入季风槽，2 hPa 盆地沿槽滑出
  4° 半径）与窗口截断系统（东北角 1000.6 深低压贴图缘，盆地漏到数据外）。定案＝
  **滑窗极值＋深度贪心吸收**：方形窗（行×列两段滑窗，min/max 结合律）内最值即候选，
  按深度排序贪心保留、切比雪夫距离不足 radius（缺省 16 格＝4°）的吸收——不漏任何
  天气尺度系统（窗最值是任何更深判据的超集），涟漪假阳性由吸收半径控制（真实场
  r=16 出 20 low/19 high，三大系统〔日本海 1000.6/东海 1007.3/台风 1009.2〕全在）；
  `minDepth`（缺省 0）作平坦背景场（合成场精确等值平台）的并列最值假阳性护栏——
  真实场上窗内环境梯度常已超槛，护栏不是过滤器。L＝红、H＝蓝＋中心 hPa 值，
  divIcon 带 aria-label（可读名称）。

### prmsl 档案

- 浅填色（等值线主导，填色只打底）：RdBu 内七段（裁去最外两对深色停靠）低蓝→白→

### 双场装载模型（本片主设计题之一）

- **`companionFile` 伴生字段而非 `files[]` 数组**（裁量）：既有十二要素的 `file`
  语义零改动（单场要素不背数组改写），双分量是「主 file＋一个伴生位」的最小加法；
  u 为主（`windu_cn.mwgrid`）、v 为伴生（`windv_cn.mwgrid`）——主场的头是合成场
  meta 的沿袭源。两文件**并行拉取、两份都齐才算装载成功**（任一失败报错含分量
  原因——半套矢量无法合成）；缓存/「拉最新」/三态语义随双场整体走，「拉最新」转发
  shortName `wind` → CLI `--element wind` 单请求产双文件（键对齐即全链路直通）。
  双分量要素无冻结基线（corpus 只冻结 tmp 单场份）——三层语义退化为 gen 双文件＞
  报错（同 dpt/rh 等无基线要素的诚实行为）。
- **装载期合成而非渲染期合成**（裁量）：`LoadedGrid.grid` 对双分量要素即
  `windSpeedGrid(u, v)` 产物（装载一次、进缓存——色斑/图例/meta/「拉最新」重渲染
  全链直读合成口径，stats 是风速分布而非 u 分量分布）；分量原值留在
  `LoadedGrid.components`（杆层原料——方向 atan2 直接吃分量原场，不经合成场）。
  「存储不动」红线不破：磁盘上的 u/v 容器仍是原值，合成只发生在显示侧
  （表 B「10u/10v 不作独立色斑、渲染目标=风速合成（前端派生显示量，存储不动）」
  的字面继承）。
- `windSpeedGrid` 合成头口径：variable **WIND**（gen CLI wind 条目 label WIND/10m
  同名——分量文件头为 UGRD/VGRD，档案 variable 字段对齐合成场）、层/单位/几何/meta
  沿 u 场头、stats 对合成值现算；任一分量 NaN → 该点 NaN（矢量未知——Math.hypot
  的 NaN 传播天然给出，与色斑/等值线的缺测纪律同口径）；两场网格几何/量纲不匹配
  显式抛错（新 GridErrorCode `grid-mismatch`，code 稳定只增不改的加法）。

### 风向杆形态（本片主设计题之二）

- **风羽（barb）而非简化箭头**（裁量，档案头注立据）：中文气象圈地面图的风羽认知
  最强（业务填图规范形态），且**速度编码**是箭头给不出的增量——简化箭头只表方向，
  方向在色斑流向上已有冗余，箭头即零增量；风羽的旗/划计数给色弱用户「方向＋速度」
  双通道冗余。实现成本可控：纯几何 SVG path（无字体/无位图/无 canvas 重绘），杆＝
  一线、旗＝闭合三角、划＝斜线，全部由 `windBarbPath(speed)` 纯函数产出（m/s 中国
  口径：**三角旗 20 m/s＋长划 4 m/s＋短划 2 m/s**——与 m/s 存储单位同源不折节
  换算；NWS 的 5/10/50 kt 口径弃用）。杆恒向上（＝风向 0°北）画在 32×32 px 的
  divIcon 内，按 `direction` 施加 SVG `rotate`（正角＝屏幕顺时针＝罗盘向），羽在
  杆左侧（北半球惯例）——**恒定像素尺寸**：zoom 下 marker 原地重定位、glyph 不缩放
  （divIcon 语义，与等值线标注同一「恒定像素可读」纪律）。
- **内核出杆位序列**（`windBarbsOf`，纯函数 Node 可测；照 contoursOf 先例——内核
  管几何与数学、适配层只装配）：u/v × 档案 `barbs` 口径 →
  [{lat, lon, direction, speed}]。抽稀＝两向同 step 格点子采样、**起点对网格中心
  对齐**（`floor(((n−1) % step) / 2)`——中国域 280×208、step 10 时列 4 起、行 3 起，
  588 格位）；**缩放无关固定步长**（v1 无 LOD——密度只由档案声明，不随 zoom 变；
  杆密度先例：真实场 502 根〔588−86 静风〕，Leaflet SVG 管线托管无压力）。
  **静风阈**（calmThreshold 1 m/s——中国气象业务惯例）以下不画杆（静风无方向可读，
  画杆即噪音；对照色斑侧：静风照画浅色不透明——「微风」是弱信号非无信号，两口径
  各自成立不矛盾）。风向＝气象**来向**口径 `dir = (270° − atan2(v,u)·180/π) mod 360`
  （u>0,v=0 → 270 西风、v>0,u=0 → 180 南风——数学锚进测试）。
- **落位**（照 addContourLayer 先例）：`addWindBarbLayer` 独立 API（与 addGridLayer
  正交组合——色斑吃合成场、杆层吃分量原场，宿主可独立取舍）；pane `mw-grid-barb`
  **z 365**（色斑 350 之上、等值线 360 之上、宿主矢量 ≥400 之下）。杆海是视觉密度件：
  svg aria-hidden（数百枚逐杆播报是读屏反可用性——速度已有色斑档冗余通道）。
- `renderForm` 加法扩展 `"filled+barbs"`（第三形态）；面板 buildOverlay 照等值线

### P2-1 等值线标注色异色多层串色（leaflet 公共 API 边界缺陷）

- **机理**：`injectContourStyle(color, highlightColor)` 把色值烤进一次性注入的全局 CSS
  （`.mw-contour-icon > span`），幂等守卫使同图第二层异色等值线时线色随 polyline 内联
  正确、标注色却固化首次注入值——线与标注不同源。demo 面板恒用缺省色不触发，属自定义
  `color`/`highlightColor` 选项的边界场景（既有测试只覆盖同色幂等）。
- **修法**：注入样式退为**纯结构**（字体/白底描边/定位，颜色全部移出）；每枚标注 span
  以内联 `style="color:…"` 携带本层色值（与 polyline 线色同源同色），`.mw-contour-hl`

## 二十四、发布前审查遗留记档（2026-10-08）——三项挂账，各归下批

v0.3 发布前全面审查（六包+工程面）修复批后，以下三项经 owner 裁决**留档挂账**、
不随本版处理，各自归入既定的下批主题：

1. **`decodeGrib2` 告警无通道、`onWarning` 缺省静默**（grib2.ts 的
   `DecodeGrib2Options`）——尾部残渣容忍路径的告警走可选回调，调用方不传则不可见，
   与「不静默」纪律有张力。根治＝grid 包引入报文级 warnings 通道（返回结构改
   `{fields, warnings}` 形态，minor 破坏性变更），应与其它 grid API 演进合并一批发，
   不为单项破一次。
2. **`renderToImageData` width 无上限**（core.ts）——width 只校验 ≥1 整数，病态大值
   （如 1e6）按 4e12 字节分配 OOM 而非抛 GridError。防护阈值待 owner 裁量
   （4096/8192 量级），定口径后小改+测试。
3. **图像高度 di==dj 方形假设**（core.ts）——高度按 nx/ny 纵横比计算，隐含经纬等距；
   di≠dj 的合法经纬网格（如 0.25°×0.5° 子域）渲染静默变形。现管道数据全等距不触发。
   待裁量：显式报错还是按真实纵横比渲染。
